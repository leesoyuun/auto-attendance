# auto-attendance

🏃‍♀️ 런닝크루 출석체크 페이지입니다 🏃‍♀️

크루장이 나온 사람만 찍으면 구글 시트에 기록되고, 포인트와 경고가 자동 계산됩니다.

## 빠른 시작

```bash
npm install
npm run dev        # http://localhost:3000
```

**시트 없이 돌려볼 수는 없습니다.** 환경변수가 없으면 어느 화면이든 무엇이 빠졌는지
알려주는 안내만 나옵니다. 목 데이터는 두지 않습니다 — 가짜 명단이 뜨면 배포가
정상인 줄 알고 넘어가게 되기 때문입니다. 설정은 기획서 8절을 보세요.

## 화면

- `/` — 출석 체크. 날짜를 과거로 바꾸면 그날 기록을 불러와 수정합니다.
  잘못 찍었으면 같은 버튼을 다시 눌러 취소하고 저장하면 됩니다
- `/solo` — 혼뛰 후기 입력. 그 달 인정 점수를 바로 보여줍니다
- `/summary` — 월별 포인트·경고·퇴출 대상과 판정 근거 (시트가 계산하지 않는 부분)

**시트가 원본입니다.** 앱은 입력 도구이고, 시트를 직접 고쳤으면 상단 **동기화**
버튼으로 다시 읽어옵니다.

## 배포

Vercel 에 올라가 있고 `main` 에 push 하면 자동 배포됩니다. 절차는 기획서 9절 참고.

**환경변수는 배포 시점에 주입됩니다.** Vercel 에서 값을 넣거나 바꿨으면 재배포해야
반영됩니다. 하나라도 빠져 있으면 화면에 빠진 변수 이름이 그대로 표시됩니다
(`missingEnv` → `SetupNotice`).

지금은 Vercel Authentication 이 켜져 있어 배포 URL 을 소유자만 열 수 있습니다.
크루원에게 공개하려면 이 보호를 끄게 되는데, 앱에 로그인이 없어서 URL 을 아는
누구나 출석을 고칠 수 있게 됩니다.

## 운영 전제

- **서비스 계정에 시트 편집자 권한이 필요합니다.** 뷰어만 있으면 명단·기록 조회는
  되지만 저장이 전부 403 으로 실패합니다. 읽기가 된다고 쓰기가 되는 것이 아닙니다
- **회원 키(`이름/출생연도`)가 `현황&회비` 와 월별 탭에서 같아야 합니다.** 한쪽이
  `영훈/89`, 다른 쪽이 `영훈/90` 이면 앱은 다른 사람으로 봅니다. 이때 그 사람을
  체크하면 `saveDay` 가 행을 못 찾아 예외를 던지고, **그날 체크한 전원이 저장되지
  않습니다** (`sheet-store.ts` 의 unknown 검사). 기록도 집계에서 누락됩니다

## 아직 안 된 것

- **로그인이 없습니다.** 위 배포 항목 참고
- **월 확정(잠금)** 은 시트에 해당 개념이 없어 미연동입니다
- **지난달 기록 수정 시 그 사이 탈퇴한 사람은 화면에 안 뜹니다.** 명단은 활동여부가
  `활동` 인 사람만 읽기 때문입니다. 그 경우 시트에서 직접 고쳐야 합니다

**시트의 `최종 합산` 과 앱의 집계는 다릅니다.** 정기러닝·혼뛰 가산과 경고 판정은
앱에서만 계산합니다 (월별 탭에 열을 추가하면 기존 수식이 깨지기 때문). 기획서 10절 참고.

자세한 내용은 기획서 9절을 보세요.

## 기술

Next.js 15 (App Router) · TypeScript · CSS Modules · Vitest

데이터는 기존 크루 시트(`런나잇_출석포인트`)의 월별 탭에 그대로 들어갑니다.
주간 20점 상한과 합산·랭크는 **이미 시트 수식**이라 앱은 날짜 셀에 값만 씁니다.
경고·퇴출 판정처럼 시트가 계산하지 않는 부분만 앱에서 계산하고,
그 규칙 숫자는 [`src/lib/scoring.ts`](src/lib/scoring.ts) 의 `RULES` 에 있습니다.
