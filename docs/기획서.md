# 런닝크루 출석 자동화 기획서

크루장이 나온 사람만 찍으면 구글 시트에 기록되는 웹앱입니다.

- **마지막 수정** 2026-09-03
- **상태** 실제 시트 연동 완료 · 혼뛰·정기러닝 완료 · 배포와 접근 제어는 미완
- **연동 시트** `런나잇_출석포인트` (테스트는 복사본으로)

> **시트가 원본입니다.** 앱은 입력을 편하게 하는 도구일 뿐이고, 점수 계산과
> 이력의 기준은 시트입니다. 앱이 시트를 대체하지 않습니다.

---

## 1. 왜 만드는가

일정이 끝나면 크루장이 월별 탭의 해당 날짜 열을 찾아 사람마다 `10` 을 입력합니다.
57명이 넘는 명단에서 열을 세어가며 폰으로 셀을 찍는 일입니다.

이 앱은 그 입력을 **검색해서 두 번 누르는 일**로 바꿉니다. 시트 구조와 수식은
그대로 두고, 입력 방식만 갈아냅니다.

### 하지 않는 것

- **점수를 계산하지 않습니다.** 주간 20점 상한이 이미 시트 수식
  `=MIN(SUM(D3:J3),20)` 으로 들어 있습니다. 앱이 또 계산하면 상한이 두 번 걸립니다.
- **캡처 이미지 인식(OCR)을 쓰지 않습니다.** 검토 결과 캡처에서 얻을 수 있는 건
  참여자 목록 하나뿐이고 노쇼는 원리적으로 나오지 않습니다. 결국 나머지를 손으로
  채워야 해서 직접 찍는 것보다 느립니다.
- **AI를 쓰지 않습니다.** 모든 판정이 산수와 날짜 계산입니다.
- **기존 시트 구조를 바꾸지 않습니다.** 월별 탭의 수식은 고정 참조
  (`=SUM(K3+S3+AA3+AI3)`)를 쓰므로 열을 추가하면 깨집니다.

---

## 2. 쓰는 사람과 흐름

**크루장 한 명**이 씁니다. 멤버는 이 앱을 쓰지 않습니다.

```
일정 끝남
  → 폰으로 앱 열기 (날짜는 한국 시간 기준 오늘로 이미 채워져 있음)
  → 나온 사람 검색해서 [참여], 온다고 하고 안 온 사람은 [노쇼]
  → 저장  → 시트의 그 날짜 열에 값이 들어가고 시트 수식이 합산
```

- 지난 기록을 고칠 때는 **날짜만 과거로** 바꾸면 그날 기록이 화면에 불려옵니다.
- 잘못 찍었으면 **같은 버튼을 다시 눌러 취소**하고 저장하면 그 칸이 비워집니다.
- 새 달이 시작되면 **탭 추가 버튼**이 뜹니다.
- 시트를 직접 고쳤으면 **동기화 버튼**으로 다시 읽어옵니다.

## 3. 화면

### 3.1 출석 체크 (`/`)

| 요소 | 동작 |
| --- | --- |
| 동기화 | 시트에서 명단과 그날 기록을 다시 읽습니다 |
| 날짜 | 기본값은 한국 시간 기준 오늘. 바꾸면 그날 기록을 불러옴 |
| 상단 칩 | `새로 기록` / `저장된 기록 수정 중` |
| 정기러닝 토글 | 화면에만 있습니다. 9절 참고 |
| 전체 명단 토글 | 검색 없이 활동 회원 전체를 훑는 모드 |
| 검색창 | 이름 일부 또는 초성 (`ㄱㅎ` → 가형/94) |
| 명단 행 | `[참여]` `[노쇼]`. 같은 버튼을 다시 누르면 취소 |
| 집계 | 참여 / 노쇼 |
| 탭 추가 | 그 달 탭이 없을 때만 나타남 |
| 저장 | 체크한 사람이 없으면 비활성 |

**전원을 훑지 않습니다.** 나온 사람과 노쇼만 찍고 나머지는 기록하지 않습니다.
66명 명단에서 10명 나왔으면 66번 스크롤이 아니라 12번 검색입니다.

**검색창을 비우면 이번에 찍은 사람만 남습니다.** 저장 전에 검토하는 화면입니다.

### 3.2 혼뛰 후기 (`/solo`)

이름을 검색해 고르고 날짜와 시간(분)을 넣습니다. 그 달 사람별 **인정 점수**가
바로 계산돼 보이므로 "왜 이 점수인지" 설명이 됩니다 — 주간 상한이 있어서
개수 × 5점이 아니고, 40분 미달은 개수에서 빠집니다.

잘못 넣은 기록은 목록에서 지울 수 있습니다.

### 3.3 월별 집계 (`/summary`)

사람별 월 포인트, 경고 수, 추첨 자격, 퇴출 대상을 보여줍니다. 퇴출 대상에는
**판정 근거가 주 단위로** 붙습니다 — 이의 제기에 답할 수 있어야 합니다.

이 화면은 **시트에 없는 것을 계산합니다.** 시트는 점수를 합산하지만 경고와
연속 불참은 따지지 않습니다.

## 4. 시트 구조 (실제)

### `현황&회비` — 명단

3행이 헤더, 4행부터 데이터입니다.

| | Name | 활동여부 | 운영진 여부 | 6월 | 7월 | … |
| --- | --- | --- | --- | --- | --- | --- |
| | 가형/94 | 활동 | 운영진 | ㅇ | ㅇ | |
| | 윤아/87 | 탈퇴 | | ㅇ | | |

- **이름이 `이름/출생연도` 형식이고, 이것이 그대로 회원 키입니다.**
  93명 전원이 이 형식이며 예외가 없었습니다. 출생연도는 바뀌지 않아서 별도
  회원ID를 만들 필요가 없습니다.
- **앱은 `활동여부` 가 `활동` 인 사람만** 다룹니다. 현재 활동 66명 / 탈퇴 27명.
  탈퇴자 행은 회비 이력 때문에 남아 있으므로 걸러내지 않으면 나간 사람이
  랭킹에 들어갑니다.
- 앱은 이 탭을 **읽고, 새 멤버를 한 줄 추가**하는 것까지만 합니다.

### `YYYY-MM` — 월별 출석

1행이 참석자 수, 2행이 헤더, 3행부터 회원 행입니다.

```
A=Rank  B=Name  C=최종 합산
1주차: D~J(7일) + K(합산)     2주차: L~R + S
3주차: T~Z + AA               4주차: AB~AH + AI      5주차: AJ~AP + AQ
```

날짜 7칸 + 주차 합산 1칸이 한 블록이고 주 수만큼 반복됩니다.

**전부 수식으로 돌아갑니다.** 앱은 날짜 셀에 값만 씁니다.

```
Rank        = RANK.EQ(C3,$C$3:$C$98,0)
최종 합산    = SUM(K3+S3+AA3+AI3)
N주차 합산   = MIN(SUM(D3:J3),20)     ← 주간 20점 상한
참석자 수    = COUNT(D3:D98)
```

**날짜 헤더는 두 가지 형태입니다.** 그 달 날짜는 일 숫자(`27`), 다른 달에서
넘어온 날은 실제 날짜 값(`8/31`). 그래서 앱은 날짜↔컬럼 위치를 **계산하지 않고
헤더를 파싱합니다.** 기존 탭들이 손으로 만들어져 주 수와 시작일이 일정하지
않기 때문입니다 (2026-08 은 4주, 2026-07 은 5주이고 `6/29`~`8/2` 를 덮습니다).
계산으로 추측하면 엉뚱한 사람의 셀에 씁니다.

**셀 값 해석**

| 값 | 의미 |
| --- | --- |
| 양수 (`10`) | 참여 |
| 음수 (`-5`, `-10`, `(5)`) | 노쇼 |
| `o` / `ㅇ` | 참여 (2026-08 탭이 점수 대신 마크만 씀) |
| 빈칸 / `0` | 기록 없음 |
| 그 외 | 기록 없음 — 조용히 참여로 처리하지 않습니다 |

### 앱이 쓰는 값

- 참여 → `10`
- 노쇼 → `-10`

저장하면 **그 날짜 열 전체를 다시 씁니다.** 체크에서 빠진 사람은 빈칸이 되어야
하므로, 있는 값만 덮어쓰면 이전 기록이 남습니다.

### `정기러닝일` · `혼뛰후기` — 앱이 만드는 보조 탭

월별 탭 셀에는 점수 하나만 들어가고, 열을 추가하면 `=SUM(K3+S3+AA3+AI3)` 같은
고정 참조 수식이 깨집니다. 그래서 이 두 가지는 별도 탭에 둡니다. 없으면 앱이
자동으로 만들고, **기존 탭은 건드리지 않습니다.**

**`정기러닝일`** — 날짜 한 열. 체크 화면의 `정기러닝` 토글을 켜고 저장하면
그 날짜가 들어가고, 끄고 저장하면 빠집니다. 이 목록에 있는 날짜의 참여가
정기러닝 참여로 계산됩니다.

| 날짜 |
| --- |
| 2026-10-12 |

**`혼뛰후기`** — 한 건이 한 줄입니다.

| 이름 | 날짜 | 시간(분) | 기록시각 |
| --- | --- | --- | --- |
| 가형/94 | 2026-10-13 | 47 | 2026-10-13 21:40 |

40분 미달도 기록은 남고 점수 계산에서만 빠집니다. 잘못 넣었으면 화면에서
지울 수 있습니다.

### 건드리지 않는 탭

`지출내용`, `dropdown` 은 앱이 읽지도 쓰지도 않습니다.

## 5. 규칙

### 5.1 상태와 점수

| 상태 | 점수 | 의미 |
| --- | --- | --- |
| 참여 | **+10** | 약속대로 나옴 |
| (기록 없음) | **0** | 애초에 신청 안 함 |
| 노쇼 | **−10** | 신청하고 안 옴 |

**"미정"은 상태가 아니라 기록의 부재입니다.** 그날 셀이 빈 사람이 곧 미참여이므로
저장할 것이 없습니다. 경고 판정은 `명단 − 그 주 참여자` 로 계산합니다.

**면책은 별도 플래그가 아니라 취소입니다.** 노쇼를 찍었다가 다시 눌러 취소하고
저장하면 그 칸이 비워지고 −10 도 사라집니다. 시트 셀 하나에 점수만 담기는
구조라 "노쇼지만 면제" 를 담을 자리가 없는데, 취소로 처리하면 자리가 필요
없습니다. 잘못 찍은 것을 되돌리는 동작과 같아서 헷갈릴 것도 없습니다.

### 5.2 포인트 (집계 화면 계산용)

| 항목 | 점수 | 상한 |
| --- | --- | --- |
| 참여 | 1회 10점 | 주간 20점 |
| 노쇼 | −10점 | 상한과 무관 |
| 정기러닝 | 월 1회 30점 / 2회 이상 **합계** 40점 | 상한 예외 (9절) |
| 혼뛰 후기 (40분↑) | 1개 5점 | 주간 10점 (9절) |

- 상한은 **얻은 점수에만** 걸고 벌점은 그 뒤에 차감합니다. 한 주에 참여 3회
  (30점→20점) + 노쇼 1회면 10점입니다.
- **월 점수는 음수까지 내려갑니다.** 바닥을 0으로 막지 않습니다.
- 월 **100점** 이상이면 월말 추첨 자격.

> **정기러닝이 상한 예외인 이유** — 상한을 걸면 월 최대 20×4주 = 80점이라
> 100점 추첨 자격자가 영구히 0명이 됩니다. 예외로 두면 80+40 = 120점이라
> 타이트하게 달성 가능합니다.

### 5.3 경고와 퇴출

**주간 요건**: 그 주에 참여가 1회 이상 있어야 합니다.

- 미충족 → **경고 1회**
- **경고 3회** 누적 → 퇴출 대상
- **첫 경고로부터 3개월** 경과 → 경고 **전부 초기화**
- **2주 연속 불참** → 퇴출 대상

주 경계는 **월요일~일요일**. 월별 집계는 각 기록의 날짜가 속한 달로 갑니다.
주가 월 경계를 넘으면(8/31~9/6) 주간 상한은 그 주에 걸고 점수는 각 날짜의 달에
나눠 귀속됩니다.

## 6. 사람을 억울하게 만들지 않기 위한 장치

| 장치 | 내용 |
| --- | --- |
| **자동 퇴출 없음** | "퇴출 대상"으로 **표시만** 합니다. 결정은 크루장이 근거를 확인한 뒤 |
| **판정 근거 표시** | 어느 주에 왜 경고인지 주 단위로 보여줍니다 |
| **일정 없는 주 면제** | 그 주에 기록이 하나도 없으면 경고를 매기지 않습니다 |
| **가입 전 소급 없음** | 가입일 이전 주는 판정에서 빠집니다 |
| **가입 주 완화** | 주 중간에 가입했으면 그 주는 판정하지 않습니다 |
| **연속 불참 완화** | 중간에 일정 없는 주가 끼면 연속이 끊깁니다 |
| **취소 가능** | 잘못 찍었으면 다시 눌러 취소하고 저장하면 됩니다 |
| **해석 실패는 무시** | 알 수 없는 셀 값을 참여로 추정하지 않습니다 |

## 7. 설계 결정과 이유

### 시트 구조를 바꾸지 않는다

월별 탭의 수식이 고정 참조(`=SUM(K3+S3+AA3+AI3)`)를 씁니다. 열을 하나 추가하면
전부 어긋납니다. 그래서 후기 제출 여부와 면책 플래그를 넣을 자리가 없고,
둘 다 규칙에서 뺐습니다(면책은 취소로 대체).

### 날짜↔컬럼을 계산하지 않고 파싱한다

기존 탭은 손으로 만들어져 배치가 일정하지 않습니다. 계산으로 추측하면 남의
셀에 씁니다. 헤더를 읽어 `날짜 → 컬럼` 표를 만듭니다.

### 요청을 묶어 읽는다

구글 시트는 **사용자당 분당 읽기 60회** 제한이 있습니다. 처음에는 탭마다 따로
읽고 `listMembers()` 가 전체 기록을 스캔해서 페이지 열 때마다 15회쯤 요청했고,
실제로 429 를 맞았습니다. `values:batchGet` 으로 묶어 3~4회로 줄이고,
429/5xx 는 지수 백오프로 재시도합니다.

### 월 탭은 버튼으로 만든다

자동으로 만들지 않습니다. **페이지를 열었을 뿐인데 시트가 바뀌면 안 됩니다.**
그 달 탭이 없으면 안내와 버튼이 뜨고, 그동안 저장 버튼은 막힙니다.

만들 때는 **직전 탭을 복제**해 서식(색·테두리·열 너비)을 물려받고 날짜·수식·명단만
갈아끼웁니다. 배치 규칙은 **빈틈 없는 월~일 주 단위**입니다.

- 시작: 직전 탭의 마지막 날짜 다음 날
- 끝: 그 달 말일이 속한 주의 일요일

어떤 날짜도 두 탭에 중복되거나 어느 탭에도 없는 일이 생기지 않습니다.
(기존 2026-08 탭은 4주뿐이어서 이 규칙과 한 주 다르지만, 이미 만들어진 탭은
건드리지 않고 새로 만드는 달부터 적용합니다.)

### 날짜는 전부 한국 시간 기준

`Intl.DateTimeFormat` 에 `timeZone: "Asia/Seoul"` 을 넘깁니다. 9시간을 직접
더하지 않습니다. **측정 결과** `2026-09-03T00:00Z` 는 KST로 09-03 이지만
America/Los_Angeles 로는 09-02 입니다. 매일 8시간 동안 날짜가 하루 어긋나고,
그러면 주 경계가 밀려 경고가 엉뚱한 주에 붙습니다.

### 가입일은 기록에서 추정한다

시트에 가입일 열이 없습니다. **기록에 처음 등장한 날**을 가입일로 봅니다.
보정하지 않으면 최근 가입자에게 가입 전 주의 경고가 소급됩니다. 기록이 없는
사람은 오늘로 두어 판정에서 자연히 빠집니다.

### 상태 버튼 두 개, 순환 탭 아님

상태가 둘뿐이라 순환 탭으로는 잘못 찍었을 때 되돌릴 방법이 없습니다.

## 8. 구글 시트 연결

**서비스 계정**으로 접근합니다. 환경변수가 없으면 목 데이터로 돌아가므로 설정
없이도 화면을 볼 수 있습니다.

1. [Google Cloud Console](https://console.cloud.google.com/) → 프로젝트 →
   **Google Sheets API** 사용 설정
2. **사용자 인증 정보 → 서비스 계정** 생성 → **키 추가 → JSON** 내려받기
3. 시트를 열고 **공유** 에서 JSON 의 `client_email` 을 **편집자**로 추가
   — 이 단계를 빼먹으면 403 입니다. **시트를 복사하면 공유가 따라오지 않습니다.**
4. 루트에 `.env.local` 작성 (`.gitignore` 에 포함)

```bash
GOOGLE_SHEETS_ID=시트_URL_의_/d/_와_/edit_사이_값
GOOGLE_SERVICE_ACCOUNT_EMAIL=이름@프로젝트.iam.gserviceaccount.com
# JSON 의 private_key. 개행은 \n 으로 두고 전체를 따옴표로 감쌉니다
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
```

`private_key` 개행 처리에서 인증 실패가 가장 많이 납니다.

## 9. 배포 (Vercel)

Next.js 서버가 필요하므로 Vercel 에 올립니다. GitHub Pages 는 정적 호스팅이라
API 라우트가 돌지 않고, 서비스 계정 키를 브라우저에 담으면 유출됩니다.

1. [vercel.com](https://vercel.com) → **Add New → Project** → 이 GitHub 레포 import
2. Framework 는 **Next.js** 로 자동 감지됩니다. 빌드 설정을 바꿀 필요 없습니다
3. **Environment Variables** 에 8절의 세 값을 넣습니다
   — `GOOGLE_PRIVATE_KEY` 는 Vercel 입력창에 여러 줄로 그대로 붙여도 되고,
     `\n` 으로 이어붙인 한 줄로 넣어도 됩니다. 앱이 양쪽 다 처리합니다
4. **Deploy**

이후 GitHub 에 푸시하면 자동 배포되고, 브랜치마다 미리보기 URL 이 생깁니다.
별도 CI 설정은 필요 없습니다 (`.github/workflows/ci.yml` 의 테스트는 그대로 돕니다).

**배포 전에 `GOOGLE_SHEETS_ID` 를 확인하세요.** 개발 중에는 테스트 복사본을
가리키고 있습니다. 실제 운영은 원본 시트 ID 로 바꿔야 하고, 그 시트도 서비스
계정에 편집자로 공유해야 합니다.

## 10. 시트 합산과 앱 집계는 다릅니다

같은 달인데 두 숫자가 다를 수 있습니다. **버그가 아니라 계산 범위가 다릅니다.**

| | 시트의 `최종 합산` | 앱의 `/summary` |
| --- | --- | --- |
| 참여/노쇼 셀 값 | 포함 | 포함 |
| 주간 20점 상한 | 시트 수식 | 같은 규칙으로 계산 |
| 정기러닝 30/40점 | **미포함** | 포함 |
| 혼뛰 후기 | **미포함** | 포함 |
| 경고·퇴출 판정 | 없음 | 있음 |

월별 탭에 열을 추가하면 기존 수식이 깨져서, 정기러닝과 혼뛰 가산을 시트
합산에 넣지 않았습니다. **추첨 자격(100점)과 경고 판정은 앱의 집계 화면을
기준으로 보세요.** 시트의 `최종 합산` 은 출석 셀만의 합계입니다.

## 12. 개발

```bash
npm install
npm run dev          # http://localhost:3000
npm test             # 단위 테스트 89개 (시트 없이 돔)
npm run test:sheet   # 실제 시트 통합 테스트 15개 — 반드시 복사본으로
npm run typecheck
npm run build
```

`npm run test:sheet` 는 **시트를 실제로 바꿉니다.** 건드리는 열을 스냅샷 떠서
되돌리지만, 원본이 아니라 복사본에 연결해두고 돌리세요.

### 구조

```
src/
  app/
    page.tsx                  체크 화면
    summary/page.tsx          월별 집계
    api/day/[date]/route.ts   그날 기록 읽기(GET) / 저장(PUT)
    api/members/route.ts      명단 읽기(GET) / 추가(POST)
    api/month-tab/route.ts    월 탭 존재 확인(GET) / 생성(POST)
    api/sync/route.ts         캐시 버리고 시트에서 다시 읽기(POST)
  components/CheckScreen.tsx  체크 화면 (클라이언트)
  lib/
    types.ts                  도메인 타입
    date.ts                   한국 시간, 주 경계
    hangul.ts                 초성 검색
    roster.ts                 활동 기간, 가입일 보정
    scoring.ts                점수·경고 엔진 (RULES 상수)
    sheet-layout.ts           월 탭 컬럼·날짜 배치
    sheet/
      client.ts               시트 REST 래퍼 (batchGet, 재시도)
      month-tab.ts            월 탭 생성
      tab-dates.ts            헤더 파싱, 셀 값 해석
    store/
      types.ts                저장소 인터페이스
      mock.ts                 개발용 목
      sheet-store.ts          실제 크루 시트
      index.ts                환경변수로 둘 중 선택
```

계산 로직은 시트와 분리된 순수 함수라 시트 없이 테스트할 수 있습니다.

### 규칙 바꾸기

`src/lib/scoring.ts` 의 `RULES` 를 고칩니다. 단 **주간 상한은 시트 수식에도**
있으므로, 상한을 바꾸려면 시트의 `MIN(SUM(...),20)` 도 함께 고쳐야 합니다.
