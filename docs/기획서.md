# 런닝크루 출석 자동화 기획서

크루장이 나온 사람만 찍으면 구글 시트에 기록되고, 포인트와 경고가 자동 계산되는 웹앱입니다.

- **마지막 수정** 2026-09-03
- **상태** 기반 구성 완료 · 규칙 엔진 검증 완료 · 구글 시트 연결은 설정 대기

---

## 1. 왜 만드는가

지금은 카톡 캡처를 보고 시트에 `참여 : 중현, 푸름, ...` 같은 텍스트를 손으로 씁니다. 두 가지 문제가 있습니다.

1. **계산이 안 됩니다.** 한 셀에 이름을 몰아넣은 텍스트로는 포인트·경고·퇴출 판정을 할 수 없습니다.
2. **손이 많이 갑니다.** 매 일정마다 사람을 세고 옮겨 적어야 합니다.

이 앱은 입력을 30초로 줄이고, 규칙 계산을 사람 손에서 떼어냅니다.

### 하지 않는 것

- **캡처 이미지 인식(OCR)을 쓰지 않습니다.** 검토 결과 캡처에서 얻을 수 있는 건 참여자 목록 하나뿐이고, 노쇼와 후기 제출 여부는 원리적으로 나오지 않습니다. 결국 나머지를 손으로 채워야 해서 직접 찍는 것보다 느립니다.
- **AI를 쓰지 않습니다.** 모든 판정이 산수와 날짜 계산입니다.
- **자동으로 퇴출시키지 않습니다.** 6절을 보세요.

---

## 2. 쓰는 사람과 흐름

**크루장 한 명**이 씁니다. 멤버는 이 앱을 쓰지 않습니다.

```
일정 끝남
  → 폰으로 앱 열기 (날짜는 한국 시간 기준 오늘로 이미 채워져 있음)
  → 정기러닝이면 토글 켜기
  → 나온 사람 검색해서 [참여], 온다고 하고 안 온 사람은 [노쇼]
  → 저장
  → 시트에 기록되고 점수·경고가 다시 계산됨
```

지난 기록을 고칠 때는 날짜만 과거로 바꾸면 그날 기록이 화면에 불려옵니다.

---

## 3. 화면

### 3.1 출석 체크 (`/`)

| 요소 | 동작 |
| --- | --- |
| 날짜 | 기본값은 한국 시간 기준 오늘. 바꾸면 그날 기록을 불러옴 |
| 상단 칩 | `새로 기록` / `저장된 기록 수정 중` / `확정된 달 · 읽기 전용` |
| 정기러닝 토글 | 켜면 30/40점 규칙으로 계산 |
| 전체 명단 토글 | 검색 없이 활동 회원 전체를 훑는 모드 |
| 검색창 | 이름 일부 또는 초성 (`ㅈㅇ` → 주원) |
| 명단 행 | `[참여]` `[노쇼]` 버튼. 같은 버튼을 다시 누르면 해제 |
| 하위 토글 | 참여 → `후기 제출`, 노쇼 → `면책` |
| 집계 | 참여 / 노쇼 / 미체크 |
| 저장 | 체크한 사람이 없으면 비활성 |

**전원을 훑지 않습니다.** 나온 사람과 노쇼만 찍고 나머지는 기록하지 않습니다. 50명 크루에서 10명 나왔으면 50번 스크롤이 아니라 12번 검색입니다.

**검색창을 비우면 이번에 찍은 사람만 남습니다.** 저장 전에 누구를 찍었는지 검토하는 화면이 됩니다.

**검색해도 없는 이름을 치면** `＋ “OOO” 새 멤버로 추가` 버튼이 나옵니다. 신규 가입자가 첫 러닝에 나왔을 때 현장에서 처리됩니다.

### 3.2 월별 집계 (`/summary`)

사람별 월 포인트, 경고 수, 추첨 자격, 퇴출 대상을 보여줍니다. 퇴출 대상에는 **판정 근거가 주 단위로 붙습니다** — 이의 제기가 들어올 때 어느 주에 왜 경고였는지 답할 수 있어야 합니다.

## 4. 데이터 구조 (구글 시트)

시트 4장을 씁니다. **열 순서를 바꾸면 앱이 다른 값을 읽습니다.** 그래서 앱이 헤더 행을 검증하고, 어긋나면 어느 열이 문제인지 알려주며 멈춥니다.

### `명단`

| 회원ID | 이름 | 가입일 | 탈퇴일 |
| --- | --- | --- | --- |
| M001 | 주원 | 2026-01-05 | |
| M012 | 윤아 | 2026-02-01 | 2026-08-31 |

- **회원ID는 절대 바꾸지 않습니다.** 출석 기록이 이 값으로 연결됩니다.
- **이름은 표시용**이라 언제든 바꿔도 과거 점수가 그대로 붙어 있습니다.
- **나간 사람의 행을 지우지 마세요.** 탈퇴일만 채우면 검색에서 자동으로 빠집니다. 지우면 과거 기록의 주인이 사라져서 연말 누적이 깨집니다.
- 명단은 크루장이 시트에서 직접 관리합니다. 명단 변경은 자주 있는 일이 아니라 전용 화면을 만들지 않았습니다.

### `출석`

| 회원ID | 날짜 | 구분 | 상태 | 후기 | 면책 | 기록시각 | 수정시각 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M002 | 2026-09-14 | 정기 | 참여 | Y | - | 2026-09-14 21:04 | |
| M011 | 2026-09-14 | 정기 | 노쇼 | - | Y | 2026-09-14 21:04 | |

- 한 사람 × 한 날 = 한 줄.
- **상태는 `참여` 와 `노쇼` 둘뿐입니다.** "미정"(신청 안 함)은 저장하지 않습니다 — 그날 행이 없는 사람이 곧 미참여입니다. 경고 계산은 `명단 − 그 주 참여자`로 하므로 미정 행이 없어도 됩니다.
- 저장할 때 같은 날짜·같은 사람의 행이 있으면 **새 행을 쌓지 않고 갱신**합니다. 중복 행이 생기면 점수가 두 번 계산됩니다.
- **기록시각은 최초 저장 시점을 유지하고, 수정하면 수정시각이 따로 남습니다.** 지난 날짜를 소급 입력해도 언제 입력했는지 알 수 있어야 합니다.

### `혼뛰후기`

| 회원ID | 날짜 | 시간 |
| --- | --- | --- |
| M002 | 2026-09-10 | 52 |

시간은 분 단위. 40분 미달은 점수에 반영되지 않습니다.

### `확정`

| 월 |
| --- |
| 2026-07 |

여기 적힌 달은 **읽기 전용**입니다. 4절 마지막과 6절을 보세요.

### 텍스트 형식은 어떻게 되나

지금까지 보던 `참여 : 중현, 푸름, ...` 형식은 위 로그에서 **자동으로 만들어 낼 수 있습니다.** 익숙한 화면을 버리지 않아도 됩니다. (현재 코드에는 미구현 — 9절)

## 5. 규칙

### 5.1 상태와 점수

| 상태 | 점수 | 의미 |
| --- | --- | --- |
| 참여 | **+10** | 약속대로 나옴 |
| (기록 없음) | **0** | 애초에 신청 안 함 |
| 노쇼 | **−10** | 신청하고 안 옴. 사전 고지로 면책되면 0 |

**신청하고 안 오는 게 신청 안 한 것보다 무겁습니다.** −10을 피하는 방법은 사전에 크루장에게 고지하는 것이고, 그래서 이 벌점은 사실 *말 없이 안 온 것*에 붙습니다.

### 5.2 포인트

| 항목 | 점수 | 상한 |
| --- | --- | --- |
| 일반 일정 참여 | 1회 10점 | 주간 20점 |
| 정기러닝 참여 | 월 1회 30점 / 2회 이상 **합계** 40점 | **상한 예외** |
| 혼뛰 후기 (40분 이상) | 1개 5점 | 주간 10점 |
| 노쇼 | −10점 (정기·일반 동일) | 면책 시 미적용 |

- **상한은 얻은 점수에만 걸고, 벌점은 그 뒤에 차감합니다.** 한 주에 참여 3회(30점 → 상한 20점) + 노쇼 1회면 10점입니다.
- **월 점수는 음수까지 내려갑니다.** 바닥을 0으로 막지 않고, 연말 누적도 월 점수를 그대로 더하므로 음수가 반영됩니다.
- 월 **100점** 이상이면 월말 추첨 자격이 생깁니다.

> **정기러닝이 상한 예외인 이유** — 상한을 걸면 월 최대 20 × 4주 = 80점이라 100점 추첨 자격자가 영구히 0명이 됩니다. 예외가 아니면 규칙 자체가 성립하지 않습니다. 예외로 두면 최대 80 + 40 = 120점이라 타이트하게 달성 가능합니다.

### 5.3 경고와 퇴출

**주간 요건**: 그 주에 참여가 1회 이상 있고, 그중 후기를 낸 것이 있어야 합니다. ("주 1회 + 참여 후기까지 필수")

- 요건 미충족 → **경고 1회**
- **경고 3회** 누적 → 퇴출 대상
- **첫 경고로부터 3개월**이 지나면 경고를 **전부 초기화**합니다
- **2주 연속 불참** → 퇴출 대상

주 경계는 **월요일~일요일**입니다. 월별 집계는 각 기록의 날짜가 속한 달로 갑니다. 주가 월 경계를 넘으면(예: 8/31~9/6) 주간 상한은 그 주에 걸고, 점수는 각 날짜의 달에 나눠 귀속됩니다.

## 6. 사람을 억울하게 만들지 않기 위한 장치

경고와 퇴출은 실제로 사람에게 영향을 주는 판정입니다. 다음을 코드로 보장합니다.

| 장치 | 내용 |
| --- | --- |
| **자동 퇴출 없음** | "퇴출 대상"으로 **표시만** 합니다. 실제 결정은 크루장이 근거를 확인한 뒤에 합니다 |
| **판정 근거 표시** | 어느 주에 왜 경고인지 주 단위로 보여줍니다 |
| **일정 없는 주 면제** | 그 주에 체크 기록이 하나도 없으면 경고를 매기지 않습니다. 참여할 일정이 없는데 미참여 경고를 주면 부당합니다 |
| **가입 전 소급 없음** | 가입일 이전 주는 판정 대상에서 빠집니다 |
| **탈퇴 후 판정 없음** | 나간 뒤의 주는 판정하지 않습니다 |
| **면책** | 사전 고지로 면책된 주는 불참으로 세지 않고 벌점도 없습니다 |
| **연속 불참 완화** | 중간에 일정 없는 주가 끼면 연속이 끊깁니다. 없는 일정에 불참할 수는 없고, 퇴출로 이어지는 판정이라 느슨한 쪽이 안전합니다 |
| **확정된 달 잠금** | 확정한 달의 출석을 고치면 이미 끝난 추첨 결과가 뒤집힙니다. 확정을 해제해야 수정됩니다 |
| **원본 보존** | 기록시각을 덮어쓰지 않고 수정시각을 따로 남깁니다 |
| **"너무 빈번" 미자동화** | 규칙에 숫자가 없어서 자동화하면 오작동합니다. 면책 횟수만 보여주고 판단은 사람이 합니다 |

## 7. 설계 결정과 이유

나중에 "왜 이렇게 했지"가 되지 않도록 남깁니다.

### 이름을 키로 쓰지 않는다

동명이인이 들어오거나 닉네임을 바꾸거나 오타가 나면 과거 기록이 끊깁니다. 회원ID를 두고 이름은 표시용으로만 씁니다.

### 점수를 시트에 저장하지 않는다

상태만 남기고 볼 때마다 계산합니다. 규칙이 바뀌면 `src/lib/scoring.ts` 의 `RULES` 상수만 고쳐도 과거 기록까지 다시 계산됩니다. 점수를 박아 넣으면 규칙이 바뀔 때 지난 몇 달치를 손으로 고쳐야 합니다.

**대신 확정 스냅샷이 필요합니다.** 소급 재계산은 이미 끝난 추첨을 뒤집을 수 있으므로, 확정한 달은 잠그고 규칙 변경은 다음 달부터 적용합니다.

### 일정을 따로 관리하지 않는다

입력은 `날짜` + `정기러닝 여부` 두 개뿐입니다.

- **장소**(광나루/올림픽)는 점수·경고 계산에 안 쓰입니다. 안내용이라 데이터로 둘 이유가 없습니다.
- **시작시각**은 지각을 뺐으므로 필요 없습니다.
- **일정 목록**은 체크 기록이 대신합니다. 기록이 있는 날이 곧 일정이 있던 날입니다.
- **정기러닝 여부만 남긴 이유**: 점수 규칙이 다릅니다. 날짜로 추론하려면 "둘째 주 월요일"의 정의(1일이 든 주 기준인지, 두 번째 월요일인지)를 확정해야 하고, 크루장이 날짜를 옮긴 달에는 틀립니다. 토글이 확실합니다.

### 날짜는 전부 한국 시간 기준

`Intl.DateTimeFormat` 에 `timeZone: "Asia/Seoul"` 을 넘겨 계산합니다. 9시간을 직접 더하지 않습니다.

**측정 결과** (2026-09-03): `2026-09-03T00:00Z` 는 KST로 09-03이지만 America/Los_Angeles로는 09-02입니다. 매일 8시간 동안 날짜가 하루 어긋나고, 그러면 주 경계가 밀려 경고가 엉뚱한 주에 붙습니다. 서버 타임존에 의존하면 배포 환경이 바뀔 때 조용히 틀립니다.

### 상태 버튼 두 개, 순환 탭 아님

상태가 참여·노쇼 둘뿐이라 순환 탭으로는 잘못 찍었을 때 되돌릴 방법이 없습니다. 버튼 두 개를 두고 같은 버튼을 다시 누르면 해제됩니다.

### 지각을 뺐다

원래 규칙 문서에 지각 벌점이 없고 "1주년 지나면서 조정 예정"이라 적혀 있었습니다. 상태를 셋에서 둘로 줄여 탭이 한 번 덜 돌고, 미뤄둔 지각 점수 문제도 사라졌습니다.

**나중에 다시 넣는다면 차감형을 쓰세요** (10점 받고 5점 깎기 = +5). 순수 마이너스로 −5점을 주면 `참여 +10 > 기록없음 0 > 지각 −5 > 노쇼 −10` 순서가 되어 **늦게라도 나온 사람이 아예 안 나온 사람보다 손해를 봅니다.** 차감형이면 `참여 +10 > 지각 +5 > 기록없음 0 > 노쇼 −10` 으로 한 방향으로 정리됩니다.

## 8. 구글 시트 연결

앱은 **서비스 계정**으로 시트에 접근합니다. 환경변수가 없으면 목(mock) 데이터로 돌아가므로, 설정 없이도 화면을 볼 수 있습니다.

### 8.1 서비스 계정 만들기

1. [Google Cloud Console](https://console.cloud.google.com/) 에서 프로젝트를 만듭니다.
2. **API 및 서비스 → 라이브러리** 에서 `Google Sheets API` 를 사용 설정합니다.
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정** 을 만듭니다.
4. 만든 서비스 계정 → **키 → 키 추가 → 새 키 만들기 → JSON** 을 내려받습니다.
5. JSON 안의 `client_email` 과 `private_key` 를 씁니다.

### 8.2 시트 공유

출석 시트를 열고 **공유** 에서 위 `client_email` 주소를 **편집자**로 추가합니다. 이 단계를 빼먹으면 권한 오류가 납니다.

### 8.3 환경변수

프로젝트 루트에 `.env.local` 을 만듭니다. (`.gitignore` 에 이미 들어 있습니다)

```bash
# 시트 URL 의 /d/ 와 /edit 사이 값
GOOGLE_SHEETS_ID=1tRnqTTTWt_EV_6v4XoQh0Q6R1zfH5xuL5AtYZa8fORA
GOOGLE_SERVICE_ACCOUNT_EMAIL=이름@프로젝트.iam.gserviceaccount.com
# JSON 의 private_key 를 그대로. 개행은 \n 으로 두고 전체를 따옴표로 감쌉니다
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n"
```

### 8.4 시트 준비

4절의 표대로 `명단`, `출석`, `혼뛰후기`, `확정` 시트를 만들고 **첫 행에 헤더를 정확히** 넣습니다. 앱이 헤더를 검증하므로 열 이름이나 순서가 다르면 어느 열이 문제인지 알려주며 멈춥니다.

### 8.5 아직 확인하지 못한 것

**구글 시트 연결 코드는 타입 검사와 빌드만 통과한 상태입니다.** 실제 시트에 붙여 읽고 쓰는 동작은 인증 정보가 있어야 확인할 수 있어서, 아직 검증되지 않았습니다. 처음 연결할 때 문제가 날 수 있는 지점:

- 서비스 계정을 시트에 공유하지 않음 → 403
- `private_key` 의 개행 처리 → 인증 실패
- 시트 이름/헤더 불일치 → 앱이 어느 열이 문제인지 알려주며 멈춤

또한 **저장할 때 `출석` 시트 전체를 다시 씁니다.** 크루 규모(수백 행)에서는 행 단위 수정보다 단순하고 안전하지만, **두 사람이 동시에 저장하면 나중 저장이 앞의 것을 덮습니다.** 크루장 한 명이 쓰는 전제입니다.

환경변수가 없으면 목 데이터로 돌아갑니다. 목 데이터는 **오늘을 기준으로 만들어지므로** 언제 열어봐도 "지난주 기록 수정"과 "확정된 달 잠금"을 눌러볼 수 있습니다. 메모리에만 있어서 서버를 재시작하면 초기화됩니다.

### 구조

```
src/
  app/
    page.tsx                  체크 화면
    summary/page.tsx          월별 집계
    api/day/[date]/route.ts   그날 기록 읽기(GET) / 저장(PUT)
    api/members/route.ts      명단 읽기(GET) / 추가(POST)
  components/
    CheckScreen.tsx           체크 화면 (클라이언트)
  lib/
    types.ts                  도메인 타입

    store/
      types.ts                저장소 인터페이스
      mock.ts                 개발용 목
```

**계산 로직은 시트와 분리된 순수 함수입니다.** 그래서 시트 없이 테스트할 수 있습니다.

### 테스트

`npm test` 로 46개가 돕니다. 경계 케이스를 덮습니다.

- 주간 상한 정확히 20점, 다른 주는 각각 상한
- **월 경계를 넘는 주에서 점수가 각 달로 나뉘어 귀속** (8/31 + 9/1 은 같은 주, 다른 달)
- 정기러닝 1회 30 / 2회 40, 상한 예외
- 혼뛰 후기 40분 미달 제외, 주간 상한
- 상한 적용 후 벌점 차감 (참여 3회 + 노쇼 1회 = 10점)
- 월 점수 음수
- 경고: 참여 없음 / 후기 미제출 / 면책 / 일정 없는 주 / 탈퇴 후
- 경고 3회 도달, 3개월 후 초기화
- 2주 연속 불참, 일정 없는 주가 끼면 연속 끊김
- 100점 추첨 자격
- KST 날짜 경계 (15:00 UTC → 다음 날 00:00 KST)

### 규칙 바꾸기

`src/lib/scoring.ts` 의 `RULES` 를 고칩니다. 숫자가 전부 여기 모여 있고, 점수를 저장하지 않으므로 과거 기록까지 자동으로 다시 계산됩니다. 단 확정된 달은 잠겨 있어 영향받지 않습니다.
